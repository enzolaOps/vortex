# Vortex for Desktop

Electron shell for the Vortex web client. It is a fork of
[stoatchat/for-desktop](https://github.com/stoatchat/for-desktop) at `v1.5.3`,
imported here as a subtree. Not affiliated with or endorsed by the Stoat
project.

The shell does not bundle the client: it loads the instance over HTTPS. The URL
is baked in at build time from `VORTEX_APP_URL` — copy `.env.example` to `.env`
and set it, or the build fails on purpose rather than shipping a client pointed
somewhere else.

## What is changed from upstream

| Area | Change |
|---|---|
| Branding | Name, app ID `io.github.enzolaOps.Vortex`, tray and autostart strings, icons from `../brand/`. |
| `assets/` | Was a private brand submodule upstream. Now generated by `node ../brand/generate.mjs`. |
| Instance URL | `VORTEX_APP_URL` at build time instead of a hardcoded `stoat.chat/app`. |
| Discord Rich Presence | Removed, along with `discord-rpc` and its exotic-subdep workaround. |
| Auto-updater | Removed. `update-electron-app` pulls releases from a GitHub repo we do not publish to. |
| Windows makers | Squirrel, AppX and ZIP removed; nobody builds for Windows here. Restore them if that changes. |
| `.github/` | Upstream's release plumbing deleted — same reasons as the web client, see `../VORTEX.md`. |

## Build

Own lockfile and `nodeLinker: hoisted`, because the native dependencies need it
and the web client next door needs `isolated`. Run every command from this
directory.

```bash
cd desktop
cp .env.example .env      # then set VORTEX_APP_URL

mise install              # tools
mise install:frozen       # packages

mise dev                  # run it
mise build                # package
mise make                 # distributables (flatpak, deb)
```

Useful during development:

```bash
# point at a local web client instead of the baked-in URL
mise exec -- pnpm start -- --force-server http://localhost:5173

# test the flatpak (after `make`)
mise exec -- pnpm install:flatpak
mise exec -- pnpm run:flatpak

# Nix
pnpm package && pnpm run:nix
```

There is no CI for the desktop app. Building a flatpak on a hosted runner is
slow and this is built by hand for one or two machines; add a workflow when that
stops being true.

## Icons

Generated from `brand/mark.svg` at the repository root, same generator as the
web client:

```bash
npm i -D sharp
node brand/generate.mjs
```

That writes `desktop/assets/` (`icon.png`, `icon.ico`, `iconTemplate.png` for
the macOS tray, and `hicolor/` for flatpak) as well as the web fallbacks.
